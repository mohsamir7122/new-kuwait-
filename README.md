# New Kuwait Research Core

إعادة بناء نظيفة وتدريجية لمشروع `KU-BO`. هذا المستودع لا ينسخ المشروع القديم
كله، بل يقبل كل مكوّن بعد إثبات استقلاله ونجاح اختبارات مباشرة عليه.

## الحالة الحالية

النسخة `0.3.1` هي `Clean Core` تعمل دون شبكة ودون بيانات خاصة. وتشمل:

- ربط الهوية باستخدام `security_code` وفترات صلاحية مؤرخة.
- تطبيع الأحداث وبناء خصائص `Point-in-Time` مع منع `Look-ahead Leakage`.
- حسابات `Liquidity` محافظة، وعدم افتراض تنفيذ صفقة بلا سيولة.
- حسابات ميكانيكية محدودة ومدققة لـ`Corporate Actions`.
- إشارات وصفية للأسعار والأساسيات والمزاج، وليست احتمالات أو توصيات.
- بصمات `SHA-256` وحفظ نتائج ذرّي يمنع الكتابة الجزئية والاستبدال الصامت.
- فواصل زمنية منقّاة ومصحوبة بـ`Embargo` لاختبارات النماذج المستقبلية.
- Parsers محدودة للبيانات الرسمية وحالات `Corporate Actions`.
- التحقق من تاريخ حالات التداول وتاريخ الأسعار البحثي دون ملء الفجوات ضمنيًا.
- ربط دليل النتائج بملفاته وبصماتها، والتحقق من حالة المحفظة.
- سياسة مضبوطة لمقاومة أعطال المصادر، وسجل ثقة موثّق باستخدام `HMAC-SHA256`.
- مسار `analyze-local` متكامل يتحقق من ملفات الأدلة وبصماتها قبل إنشاء ملخص
  بحثي وصفي ذرّي، دون اتصال بالشبكة أو توصية تداول.

لا تشمل هذه المرحلة جمعًا حيًا، أو نموذجًا تنبئيًا، أو `Backtest`، أو توصية، أو
تنفيذ تداول. توجد هذه الحدود داخل ناتج الفحص الآلي نفسه، وليست ملاحظة تسويقية.

## التشغيل

```bash
PYTHONPATH=src python -m kubo self-check
PYTHONPATH=src python -m unittest discover -s tests -v
PYTHONPATH=src python -m kubo analyze-local \
  --bundle examples/local_bundle \
  --output /tmp/new-kuwait-example-result
```

يمكن أيضًا تثبيت الحزمة محليًا ثم تشغيل:

```bash
python -m pip install --no-deps --no-build-isolation .
kubo-core self-check
```

## سياسة الاختبار العملية

لا يستهدف المشروع رقمًا كبيرًا للاختبارات. يُضاف الاختبار فقط عندما يغطي عقدًا
أو مسار فشل أو سلوكًا مختلفًا. يشغّل `CI` المجموعة الكاملة مرة واحدة على Python
`3.13` لكل تغيير برمجي، ويجري `Compatibility Smoke` خفيفًا على الحدين المدعومين
Python `3.11` و`3.14` أسبوعيًا أو عند الطلب اليدوي. تغييرات التوثيق وحدها لا
تشغّل الفحوص البرمجية، والتشغيل القديم يُلغى إذا وصل Commit أحدث.

## سياسة النقل

كل مرحلة نقل يجب أن تضيف المكوّن واختباراته المباشرة وتحدّث سجل النقل. لا تُنقل
المصادر أو الـ`Workflows` أو الـ`CLI` القديم لمجرد وجودها؛ يلزم إثبات وظيفة حقيقية
وحدود واضحة ونجاح الاختبارات داخل هذا المستودع.

التفاصيل في [سجل النقل](docs/MIGRATION.md)، ونتيجة فحص كل ملف وفرع في
[ملخص التدقيق](docs/LEGACY_AUDIT_AR.md).
